# ДЗ: метод кросс-энтропии в обучении с подкреплением

Основной файл — `task_crossentrophy_rl.ipynb`. В нём сохранены исходные условия задания, код, результаты запуска и графики. Комментарии к решению и дополнительные объяснения вынесены в этот README. Здесь объясняется решение и то, как рассказать о нём на защите.

## Как запустить

Нужен Python 3.12 или новее. Из папки задания:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ipykernel install --user --name crossentropy --display-name "Crossentropy"
```

Открыть ноутбук в VS Code или Jupyter, выбрать это окружение и выполнить все ячейки сверху вниз. Эксперименты требуют времени: в каждом запуске много эпизодов. Для просмотра уже сохранённых графиков запускать обучение заново не нужно.

`results.json` содержит численные результаты, а `taxi_policy.npy` — итоговую таблицу вероятностей Taxi. Эти файлы создаются при запуске из папки задания. Используется seed 42 для обучения и seed 2026 для отдельной проверки. Совпадение чисел между разными версиями библиотек не гарантируется.

## Что говорить в начале защиты

«Я реализовал метод кросс-энтропии для двух сред. В Taxi состояние дискретное, поэтому политика — таблица вероятностей действий. В CartPole состояние состоит из четырёх чисел, поэтому вероятности предсказывает нейросеть. На каждой итерации я собираю эпизоды, выбираю лучшие по суммарной награде и обучаю политику повторять действия из этих эпизодов. Для Taxi сравнил процентиль и размер пакета, затем добавил усреднение и проверил итоговую политику на новых играх».

## 1. Основные понятия

**Состояние** — информация, которую агент видит перед действием. **Действие** — выбранный шаг. **Награда** — число, которое среда возвращает после шага. **Эпизод** — одна игра от сброса среды до завершения или ограничения по времени.

Суммарная награда эпизода:

```text
R = r_1 + r_2 + ... + r_T
```

Здесь нет дисконтирования: все награды просто складываются.

**Политика** задаёт вероятность каждого действия в текущем состоянии. Политика стохастическая: действие выбирается случайно с этими вероятностями. Это помогает исследовать разные варианты.

## 2. Taxi: что хранится в таблице

В Taxi 500 состояний и 6 действий. Состояние кодирует положение машины на сетке 5×5, положение пассажира (4 остановки или уже в машине) и пункт назначения:

```text
25 × 5 × 4 = 500
```

Действия: юг, север, восток, запад, посадка и высадка. Обычный шаг даёт −1, неправильная посадка или высадка — −10, успешная доставка — +20. Поэтому выгодно доставить пассажира быстро и без неправильных действий.

`policy` — массив размера `(500, 6)`. `policy[s, a]` означает вероятность выбрать действие `a` в состоянии `s`. Каждая строка неотрицательна и в сумме равна 1. В начале везде `1 / 6`: предпочтений ещё нет.

`generate_session` сохраняет состояние **до действия**, само действие и сумму наград. Если записать `next_state` вместо `state`, получится неправильная обучающая пара: действие будет связано с состоянием, в которое оно привело.

В Gymnasium `reset()` возвращает `(state, info)`, а `step()` — `(next_state, reward, terminated, truncated, info)`. Останавливаю цикл при любом из двух флагов. `terminated` означает завершение по правилам игры, `truncated` — внешнее ограничение, например по числу шагов.

## 3. Отбор элитных эпизодов

В `select_elites` считаю порог через `np.percentile`. Например, при процентиле 70 примерно верхние 30% эпизодов становятся элитой. Все состояния и действия этих эпизодов объединяются в исходном порядке.

Используется `reward >= threshold`, поэтому эпизоды с наградой ровно на пороге тоже попадают в элиту. При одинаковых наградах элитных эпизодов может быть больше 30%.

Пример: награды `[3, 4, 5]`, процентиль 50, порог 4. Останутся эпизоды с наградами 4 и 5. Отбираются целые эпизоды, а не отдельные шаги с большой мгновенной наградой.

## 4. Обновление политики

В `update_policy` считаю, сколько раз каждое действие встретилось в каждом состоянии в элитных эпизодах, затем делю на общее число посещений состояния:

```text
new_policy[s, a] = count(s, a) / sum_b count(s, b)
```

Например, если в состоянии дважды выбрали действие 0 и один раз действие 2, новые вероятности — `2/3` и `1/3`. Остальные равны нулю.

Если состояние не встретилось, в базовой функции ставлю равномерную строку. Это требуется в задании и исключает деление на ноль. В настроенном обучении отдельно заменяю такие строки старыми вероятностями, чтобы не терять уже накопленный опыт.

Обновление сглаживаю:

```text
policy = (1 - learning_rate) * policy + learning_rate * new_policy
```

При `learning_rate=0.5` старая и новая политики имеют одинаковый вес. Это не скорость градиентного спуска, а коэффициент смешивания двух таблиц. Суммы строк остаются равны 1, потому что смешиваются два распределения.

## 5. Почему это называется методом кросс-энтропии

Идея: подобрать распределение действий, которое лучше объясняет успешные примеры. Это соответствует максимизации логарифмов вероятностей элитных действий:

```text
sum_i log policy[action_i | state_i]
```

Или минимизации отрицательной суммы — кросс-энтропии с действиями из элиты как правильными метками. Для табличной политики решение получается через частоты. Для нейросети используется обучение классификатора.

Это обучение с подкреплением, потому что удачные примеры выбираются по награде среды. Внутри обновления нейросети задача уже похожа на обычную классификацию: состояние — признаки, действие — метка. Правильных действий заранее нет, их берём из собственных удачных игр.

## 6. Сравнение параметров

Сравнил процентили 50, 70 и 90 при 250 эпизодах на итерацию. Затем сравнил 100, 250 и 500 эпизодов при процентиле 70. На каждый вариант приходится 40 итераций. Перед каждым запуском политика снова равномерная, генераторы случайных чисел сбрасываются.

Большой процентиль означает более строгий отбор: лучшие эпизоды сильнее влияют на обучение, но данных становится меньше. При слишком строгом отборе можно закрепить случайно удачную стратегию и потерять исследование других действий. Малый процентиль даёт больше данных, но включает больше неудачных действий.

Большой пакет лучше покрывает состояния и обычно уменьшает шум, но требует больше игр и времени. На графике по итерациям вариант с 500 играми получает больше опыта, чем вариант со 100. Поэтому это сравнение качества на итерацию, а не при одинаковом вычислительном бюджете.

Результаты ниже относятся к одному запуску. Чтобы утверждать, что один параметр надёжно лучше другого, нужны несколько seed и оценка разброса.

## 7. Как получил положительную награду Taxi

В этой части сделал несколько изменений:

- Один сеанс состоит из 10 эпизодов с разными начальными состояниями. Его оценка — средняя награда. Состояния и действия всех 10 игр сохраняются для обучения.
- Усредняю последние 10 новых таблиц политики, затем смешиваю результат со старой таблицей.
- В состояниях, отсутствующих в элите, сохраняю старую политику.
- Использую `info["action_mask"]`, которую возвращает сама среда, чтобы исключать недопустимые посадки, высадки и движения в стену.

Маска не сообщает кратчайший путь и не выбирает действие за агента. Она только убирает действия, которые в данном состоянии не меняют его. Если после применения маски вся вероятность стала нулевой, выбираю равномерно среди разрешённых действий.

Здесь 75 групп по 10 игр, то есть **750 эпизодов на итерацию**, а не 75. Средняя награда группы и сумма наград десяти игр — разные величины; для отбора использую именно среднюю.

Усреднение уменьшает влияние случайного начального положения пассажира и машины. Но я одновременно добавил маску и сохранение старых строк, поэтому результат нельзя объяснять только усреднением. Чтобы измерить вклад каждого изменения, нужен отдельный эксперимент, где меняется только один фактор.

Обучение останавливается, когда средняя награда последних 10 итераций больше 5, либо после 150 итераций. После этого проверяю политику на **500 новых эпизодах** без обучения. Проверка тоже использует маску: это та же политика выбора действий, что и при обучении.

## 8. CartPole: зачем нейросеть

Состояние CartPole — четыре числа: положение и скорость тележки, угол и угловая скорость шеста. Два действия толкают тележку влево или вправо. За каждый шаг, пока эпизод продолжается, начисляется +1. Поэтому суммарная награда равна длительности игры; предел CartPole-v1 — 500 шагов.

Таблица для всех возможных вещественных состояний не подходит. Использую `MLPClassifier` с двумя скрытыми слоями по 20 нейронов и активацией `tanh`. На входе четыре признака, на выходе вероятности двух действий.

`agent.predict_proba(state.reshape(1, -1))[0]` возвращает вероятности для одного состояния. `reshape` добавляет размер пакета: классификатор ожидает двумерный массив. Затем случайно выбираю действие с этими вероятностями.

В начале вызываю `partial_fit` на двух копиях одного состояния с метками 0 и 1 и передаю `classes=[0, 1]`. Это инициализирует сеть и сообщает оба возможных класса. Это не обучающие примеры хорошего поведения, а техническая инициализация.

Дальше собираю 100 эпизодов, выбираю элиту с процентилем 70 и вызываю `agent.partial_fit(elite_states, elite_actions)`. В отличие от обучения с нуля, `partial_fit` продолжает обучение и сохраняет состояние оптимизатора между вызовами.

Останавливаю обучение при средней награде пакета больше 190: это порог из задания. Затем проверяю модель на 100 новых играх. Порог 190 не означает, что достигнут максимум 500 или решён любой возможный начальный случай.

## 9. Вопросы, которые могут задать

**Почему случайно выбираешь действие, а не берёшь максимальную вероятность?** Чтобы исследовать разные действия. Немедленный переход к `argmax` может закрепить раннюю ошибку. И при обучении, и при проверке оставляю стохастический выбор.

**Почему обучаешься по всем шагам элитного эпизода?** Метод считает действия хорошего эпизода полезными примерами. Это простое приближение: в хорошем эпизоде тоже могут быть лишние действия.

**Почему награда Taxi может снова упасть?** В разных пакетах встречаются разные начальные состояния. Некоторые состояния редко попадают в элиту, часть опыта теряется, а вероятности полезных действий могут стать слишком маленькими. У базового метода нет гарантии монотонного улучшения.

**Что будет при процентиле 100?** Останутся эпизоды с максимальной наградой. Их может быть несколько, но обычно данных мало. При процентиле 0 попадут все эпизоды.

**Чем метод отличается от Q-learning?** Здесь не обучается таблица ценности `Q(s, a)` и нет обновления Беллмана. Я напрямую обновляю распределение действий по хорошим эпизодам.

**Где здесь градиентный спуск?** В обучении нейросети CartPole. В Taxi новые вероятности считаются обычными частотами.

**Почему график недостаточен для проверки результата?** Обучающий пакет влияет на обновление модели. Отдельные новые эпизоды позволяют проверить, работает ли итоговая политика без дальнейшего обучения.

**Что проверяют assert?** Изначально равномерные вероятности, корректный отбор элиты, частотное обновление, отсутствие NaN и нормировку строк. В конце отдельно проверяется положительная средняя награда Taxi и награда CartPole больше 190.

**Что можно улучшить?** Повторить сравнения на нескольких seed, отдельно проверить эффект каждого изменения и сравнить варианты при одинаковом числе эпизодов.
